# Offline use

Open the app's full `/vocab-app/` address online first. Wait for the Hebrew "ready for offline practice on this device" message before airplane mode. Keep/open the same full address, or add that page to the iPhone Home Screen. Home Screen installation is convenient, not required by the implementation. A first-ever offline visit cannot install the app. Clearing Safari website data or storage eviction removes offline readiness; reopen online to prepare again. A successful Chromium check does not replace a real iPhone Safari test.

The service worker atomically caches the app shell, vocabulary, and pinned Firebase SDK scripts. Offline navigation falls back only to an app HTML document, never HTML for a missing JS/JSON request. Progress stays in localStorage, including a pending flag and revision. On reconnect or foregrounding, sync reads the server record, merges it with local state, and retries delivery. Changes made during an upload remain pending until a subsequent upload completes. Firebase IndexedDB persistence is enabled where supported; the app queue also survives reload without it. Switching accounts saves/loads separate local snapshots rather than uploading one account's work to another. Initial sign-in adopts guest work.

Tests: `node scripts/offline-browser.test.cjs` checks the actual service worker, cached Firebase scripts, closing/reopening offline, vocabulary/practice, pending persistence, and reconnect. `node scripts/reconnect-browser.test.cjs` tests app-level merge/queue/ack/account handling with an explicitly mocked transport. These do not claim an authenticated production Firestore write or iPhone Safari end-to-end test.
